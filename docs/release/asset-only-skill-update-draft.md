## 追加する判断

- 画像だけの依頼では、アプリのバージョンやビルドを機械的に増やさず、対象がスクリーンショットか、ヘッダ／検索結果／イベント向けCreative Assetかを区別する。
- 承認済みアプリではAsset Libraryの画像単独審査が利用できる。ライブラリへのアップロード、審査提出、承認、公開ページへの配置、実ストアでの表示確認を別状態として保存する。
- 公開中バージョンのスクリーンショット枠が編集不可の場合、単独審査だけで掲載更新完了としない。Product Page Optimizationのトリートメント適用、または次バージョンへの配置を選ぶ。Creative Assetは承認済み画像を現行ヘッダ等に選択してPublishする別工程。
- 元画像の配置を外してもAsset Library本体は消さず、戻せるようにする。変更後のlocale、デバイス枠、枚数、並び順を保存し、価格の旧画像が混ざっていないことを確認する。
- 中型／大型等の必須要件はその都度Apple公式とConnectの枠に照合する。Simulatorの製品名と提出枠を同一視しない。
- 画像だけの提出に新しいアプリバイナリを含めない。機能改修が同時依頼された場合、その実装と本番バイナリの公開状態を分けて報告する。

## 公開経路に関する今回の追加検証

公開中のスクリーンショットを差し替える依頼では、PPOを使うなら最初にその配置を決め、PPO側からまとめて審査提出する。先に同じ画像をAsset Library単独で提出すると、PPO追加時に「同じスクリーンショットが別の提出物に含まれる」ため止まることを実測した。未提出のライブラリアセットを使うか、既存の審査承認を待って再利用する。既存提出の変更は内容・状態・影響を確認して判断し、単に整理するために取り下げない。

今回に限り、画像12件だけの待ち状態の提出を取り下げてPPOへ統合し、PPO1項目として審査待ちになった。新バイナリ・IAP・公開中の配置には触れていない。50%の公開テストは通常の直接差し替えとは異なるため、具体的な表示範囲への承認を取得した。取得済み承認は継続時に再度求めない。

通常掲載への適用はまだ未実施。成功後、PPOレビューの承認、テスト状態、Apply Treatment to Current Product Page、対象版の確認、実ストア反映を記録してから共有スキルへ反映する。
