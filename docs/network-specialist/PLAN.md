## 調査した基盤

- `project.yml`: QualificationApp テンプレートで資格別 JSON のみ同梱。
- Models: version 1、単一画像、文字列選択肢。StudyData は欠落キーの移行に対応。
- Planner / Collections: freeQuestionIDs による絞込み、年度順、復習、概念関連出題を再利用。
- MasteryEngine: 変更しない。模試の実回答のみ終了時に渡す。
- Store: 原子的保存、破損ファイル保護。模試記録は集計値のみで、途中保存なし。
- SessionView: 既存模試は回答を即時記録するため新仕様には使えない。
- PurchaseManager / AdsService: StoreKit 2 の検証済み非消耗型権限、解決前広告抑止を保持。
- ContentView / Library / Insights / QuestionCollection: 共通入口・履歴・アクセス制御を拡張。
- Tests / UITests / demo-safety: 既存の基準と学習体験を回帰テストする。

5. 資格専用ターゲット・課金設定、共通のアクセス防御、旧データ回帰。
6. **Phase 2** 形式の異なる公式10問を手作業校合・独自解説し統合。部分セットを公式模試として提供しない。

10. **Phase 6** 両アプリのビルド・単体/UIテスト、購入/復元、実機アクセシビリティ、リリース。

## 設計決定

- 既存の stem / choices / explanation / imageName / correctIndex の意味を変更しない。
- bodyBlocks があるときはそれを本文表示の正とし、stem は全文の検索・一覧用テキスト。
- 選択肢ブロックは choices と同じ添字。画像のみの選択肢にも音声説明を保持。
- 模試の実行中状態はPendingMockを使用。期限はバックグラウンドでも進む。戻る/再起動では途中状態を消去し，再開機能は提供しない。採点済みの回答・結果は保持する。
- 結果UUIDを採点の冪等キーに使用。結果・実回答・Mastery更新・途中状態消去を一回の原子的書込みにまとめる。
- 未回答は問題別結果に残すが Answer を作らず、習熟度と誤答回数を更新しない。
- 固定模試の questionIDs は明示順。構成問題が全てアクセス可能な場合のみ開始。
- 未完成問題数に合わせて試験設定を25問から変更しない。未完成セットを25問模試と偽らない。現在は全対象年度が25問揃い、公式原問順の固定セットとして登録済み。
- 予想セットの表示名は設定で変更可能。ID・履歴は固定。
- 開発用の原本・レビュー台帳・スクリプトはアプリへ同梱しない。
