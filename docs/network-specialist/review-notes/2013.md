## 仕様の根拠

- Fluke Networksの正文で差動/より/対間pitch差を直接確認。IEEE802.3の資料`geoff1.pdf`を直接取得し2/8頁の4対/各full-duplexを確認。TIA854別規格の出版者検索書誌は参照したが，規格本文の販売サイトは403で取得できず，**TIA規格全文を読了したとはしない**。ウは原名1000BASE-TXを変更せず，4対各双方向250という1000BASE-Tとの混同を説明する。
- RFC4271正文の初期経路交換/増分更新/no periodic table refresh/KEEPALIVE，Cisco公式FCoE Overview正文のEtherType/L2/PFC，RFC959 §2.3/3の制御/データを直接参照。FCoEの原FC保持やMTUについてもCisco公式検索資料と整合を確認し，TCP/UDPで運ぶ説明にしない。
- RFC6146正文のIPv6-onlyからIPv4 server変換，RFC7526のanycast 6to4非推奨と2002::/16を廃止しない記述を直接確認。全6to4が同じ時点で廃止されたとはしない。
- RFC1661のfull-duplex/複数上位/HDLC-like/認証，RFC1962のCCP，RFC903のhardware→protocoladdressとbroadcastを直接確認。原問のリンク層をDHCPへ置換しない。
- RFC9293 §3.5/Fig6の基本3ウェイ，SYN一つ/ACK非消費を直接参照。再送や同時オープンを勝手に原誤肢の救済条件にしない。
- RFC9110のhttps既定TCP443，RFC2047のencoded-word/addr-spec内禁止，RFC5322のdisplay-nameとangle-addr，RFC6532のUTF-8ヘッダを直接確認。Base64の符号化を暗号化/本人認証にしない。
- Asahi Net公式の外部TCP25制限/固定IP例外/自社メールサーバ許可を直接確認。例外範囲は全ISPに一般化しない。RFC8314正文の465 implicitTLS/587 STARTTLS投稿保護を確認し，認証だけで25遮断を突破するとはしない。
- RFC5358正文の再帰の外部提供制限/権威と再帰分離/公開権威も増幅可能を直接確認。VLANもbroadcast域の分離で，認証/全ICMP遮断/L3通信全禁止ではないと各肢レビュー。
