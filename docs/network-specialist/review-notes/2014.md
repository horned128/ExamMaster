## 仕様/教育品質の別観点

- RFC4291リンクローカルを別リンクへ転送しない規定，RFC3849文書用2001:db8を直接確認。グローバル取得失敗専用/自PC専用/IPv4埋込みとの区別を全肢へ反映。
- RFC3596のAAAA128ビットとip6.arpa，RFC4861の近隣link-layerアドレス解決，RFC4271パス属性を直接参照。DNS参照先/値，IPv6のNS/NAとARP，AS_PATH長/ルータhopを分ける。
- RFC5890のA-label/U-label/Punycode，Unicode UTS #46（直接取得時2026-08-31版）の§1.3.1/4.2と全角マッピング例を直接確認。IDNA2008でそのまま有効なラベルと入力互換処理を分け，変換を暗号化/安全性保証としない。
- RFC4033のdata origin authentication/integrity/no confidentialityを直接確認。原文『送信者』をデータ出所として説明し，ライブのTLS相手認証，TSIG，DoH/DoTとの違いを明記。
- RFC8446 §1.2のstatic RSA/DH廃止と（EC）DHE/証明書署名の役割を直接確認。X.509/主体公開鍵/CA秘密鍵署名/CA公開鍵検証を分ける。SSLという原文を保持して現行非推奨を別補足。
- RFC3580 §1/1.1のAuthenticatorがRADIUSクライアントとなることと三者定義を直接確認。PC/AP/認証情報管理サーバの組合せ全4肢を別比較。
- RFC4954のAUTH exchangeとRFC8314の投稿/アクセスのTLS推奨を直接確認。旧POP before SMTPの一時IP許可と共有/NAT制約を説明し，現在も推奨方式としない。
- STPはL2/ループ防止/有効treeでbroadcast転送/BID比較を分け，現行拡張systemIDにも配慮。IPv4マルチキャストの用途予約/可変範囲/TTLを別確認。RSVPの資源予約と優先度/RTSP/RTPを区別し，timestampだけで時間差保証としない。
- TCPの受信/輻輳window，FEC/ARQ，仮想回線/datagramを別確認。ビヘイビア法は挙動観察とhash/パターンを分け，アの『非存在なら検知』を無断訂正しない。通常PCで危険な実行を推奨せず，動的解析の検知限界も明記。
- CSIRTの対応目的，メモリバンクの並列帯域/セル遅延，リバース解析/リファクタリング/再構築の差も全肢で比較。
