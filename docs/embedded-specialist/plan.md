# ExamMaster ブラッシュアップ ＋ ES（エンベデッドシステムスペシャリスト）アプリ計画

2026-11-08 合意。参考元: 自作の静的Webアプリ `~/Downloads/ipa`（開発終了・参考のみ。コード・文章・図は自由に移植可）。

## 方針

- **アプリ自体の説明は短く**（各画面の補足は1行まで、残りは (i) か設定へ）。
- **学習コンテンツは丁寧に**: 問題・解説・教科書・弱点マップ・用語集は ipa Web版のように専門用語を丁寧に説明する。
- 学習の核は「どんな問題で、なぜその選択肢が正解で、なぜ他が不正解か」を理解できること。
- **マスコットは派手に動かす**（文字情報ではないので）。解きたい・正解したいと思わせる、楽しい演出にする。
- ES を最初の利用者にして、プラットフォーム改善と ES アプリ作りを並行して進める。改善は Core/Views に入れ、毎回 ES の実データで確かめる。
- ipa のデータは一度だけ変換して取り込み、以後は ExamMaster の JSON を正本にする。

## 共通プラットフォーム（全資格に適用）

### 問題画面
- 選択肢を押した瞬間に採点する。手応えの入力は出さない（MasteryEngine では常に「普通」扱い）。
- 模擬試験（採点まで選び直せる）と Recall モード（「選択肢を見る」まで隠す）は今のまま。
- 問題の上に「前回○×・解答回数・ミス回数・☆」を小さく出す。kind と出典は1行にまとめる。

### 解説
- 画面下から緑または赤のパネルがせり上がり、マスコットの大きな反応・短い一言・「次へ」ボタンを出す。
- パネルの上の領域:
  1. 選択肢を残したまま色と○×を付け、各選択肢の直下に理由を1〜2行で出す（開いた状態で表示）。
  2. 「なぜ正解か」の解説（図・表あり）。steps はここに統合する。
  3. 「関連知識」「用語メモ」は閉じた1行ずつ（開くと中身が出る）。
- 復習目安バッジは削除する。
- Reduce Motion・低電力モードのときは、マスコットは止めた絵にして触覚フィードバックだけにする。

### 演出
- 連続正解（3・5・10回）で反応を段階的に大きくする。間違えたら静かに0へ戻す。ライフ制はなし。
- セッション完了画面: マスコットのダンス、正答数、はねのカウントアップ、あしあと＋1、今日の目標リング。文字は数字と一言のみ。
- 効果音（正解・不正解・コンボ・完了・進化）: スクリプトで自作。初期設定はオンで、設定で切り替えられる。消音モードでは鳴らさない。
- 進化のゲージ: ホームのマスコットの下に4段階のアイコンを並べ、今の段階内の進み具合を塗りで示す。数字は出さない。8割を超えたら「もうすぐ進化！」。最高到達点で表示し、戻さない。
- 進化の瞬間: 全画面で光り、シルエットが変身し、専用の効果音を出す。

### 文字
- アプリ内の文字サイズ設定は作らず、Dynamic Type に従う。標準のとき、本文 17pt・選択肢の理由 15pt・補足 13pt。
- 本文の行の高さは文字の約1.6倍。長文は標準書体（SF＋ヒラギノ）、見出しと数字は丸みのある書体、コードは等幅。
- iPad では本文の幅を約640ptまで。表は横スクロールにし、文字は縮めない。値は `Design.swift` の文字スタイルにまとめる。
- iPhone SE と Pro Max で、標準の文字サイズと大きい文字サイズの両方を確認する。

### データ形式
- text ブロックで文字装飾の記法を使えるようにする: Markdown の一部（太字・箇条書き・リンク）と `==マーク==`（紛らわしい語を赤くする）。
- `Question.related: [ContentBlock]?`（関連知識）。教科書へのリンクは `exammaster://textbook/<章>#<節>`。
- `Question.references` を正式な項目にする（AP の240問ですでにデータがあるのに、今は読み捨てている）。「参考資料」として表示する。
- `Question.glossaryTermIDs: [String]?`。取り込みスクリプトが事前に計算して書き込む。
- `kind` に `original` を追加し、「オリジナル」と表示する（電験の「予想」とは区別する）。
- 図は PNG @3x（SVG はヘッドレス Chrome で変換）。ダークモードでは白いカードに載せる。
- 資格 ID のハードコード分岐（`ContentView.swift:207`、`LibraryView.swift:250` など）は `qualification.json` の設定に置き換える。例: `libraryStyle: years|sets`、`subcategoryDrill`。教科書や用語集の有無はファイルがあるかで判定する。

### 教科書モジュール
- 本文の章・節は ContentBlock で書き、問題と同じ表示部品で描く。callout ブロック（「試験に出る」「組込みでは」「物理的には」）と、開閉式の確認問題を追加する。
- レイヤーマップは JSON で定義する汎用の SwiftUI 部品（段・用語チップ・詳細パネル）。NW の OSI 層にも使い回せる。
- 旅は手順の一覧と、画像にしたタイミングチャートで表す。
- 用語集（資格ごとの `glossary.json`）の一覧画面と、全文検索（問題・用語・教科書）は教科書タブに置く。
- 問題から教科書へはシートで開く（演習は中断しない）。教科書から関連問題を押すと1問だけ解くシートを開き、結果は解答履歴と習熟度に記録する。

### タブ
- ホーム／年度別（または「セット」）／分野別／復習（苦手問題とブックマークを切り替え）／教科書。教科書がない資格では、このタブに用語集を出す。どちらもない資格は4タブ。

### 弱点マップ（「学びのマップ」を作り直す）
- 全資格: テーマを習熟度で色分けし、正答率・復習待ちの数・本番での出題の多さを合わせた優先度で並べる。ワンタップでそのテーマの弱点を出題できる。
- テーマごとの丁寧な解説（どんな分野か・試験での問われ方・教科書へのリンク）は `qualification.json` に持たせる。ES の分だけ今回書き、他の資格はあとで追加する。
- 全体図がある資格では、全体図の用語チップも関連問題の習熟度で色分けする。

## ES アプリ

- 表示名「ピヨトレ！エンベデッドシステムスペシャリスト」、資格ID `embedded-specialist`、Bundle ID `jp.hino.piyotre.embeddedspecialist`。
- 配色は基板をイメージした琥珀色や深緑の系統。アイコンは既存と同じ作り方で作る。料金体系は他と同じ（無料＋広告＋買い切り）。
- 収録するのは午前II（科目A-2）の300問。午後と午前Iは入れない。ストアの説明文に「午前II対策」と明記する。
  - セット1〜11（本番と同じ分野構成の25問）は模擬試験のセットにする（25問・40分・合格60%）。セット12は補強セット（セキュリティ）。
  - 科目は「午前II」の1つ。分野は ipa の大分類（10分野）とし、中分類でもう1段絞り込める。
  - 「年度別」タブは「セット」タブになる。
- 無料はセット1・2（50問）。教科書と用語集は全部無料。
- 教科書: 電子回路の基礎（8章）、全体図（用語チップ157個と旅3本）、要点まとめ（10章）。印刷版とPDFは入れない。
- 用語集: 993語（NW の用語も含む）。
- オリジナル問題102問: 取り込み時に自動チェックをかける（正解番号と選択肢ごとの解説の○が一致するか、4択か、IDが重複しないか など）。リリース前に確認するためのチェックリストを docs に用意する。→ `docs/embedded-specialist/original-review.md`（`tools/embedded-specialist/review_originals.py` で作り直す）

## 進め方（各段階でテストが通ったらコミットする。push はしない。区切りごとに handoff してセッションを切り替える）

0. denken3 の作業中の変更をコミットする
1. データモデルの拡張、表示部品、文字スタイル、資格IDによる分岐を設定に置き換える
2. ES の取り込みツール（HTML→記法、SVG→PNG、用語の抽出、検証）と ES ターゲット（配色・アイコン・セット一覧・無料2セット）
3. 問題画面と解説画面の作り直し
4. 演出（マスコットの反応、コンボ、完了画面、効果音、進化のゲージと進化の演出）
5. 教科書モジュール（本文、callout、レイヤーマップ、旅、用語集、検索、タブの再編成、問題と教科書の相互リンク）
6. 弱点マップ（全資格共通の部分、ES のテーマ解説、全体図の習熟度による色分け）
7. 既存画面のアプリ説明の文字を削る
8. オリジナル問題の確認用チェックリスト（App Store への申請準備は別の作業）

各段階で、AP・FE・NW・電験三種のユニットテストを実行する（作り直し前から落ちていた既知のテストは除外して判断する）。あわせて、電験のように選択肢ごとの解説がない資格でも表示が崩れないことをシミュレータで確認する。
